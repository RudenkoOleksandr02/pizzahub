# PizzaHub. Демонстраційний вебзастосунок замовлення піци

PizzaHub («Pizza Hub - неймовірна насолода») - це піцерія-вітрина, яку я зробив на Next.js та Prisma, щоб показати, як будую повноцінні застосунки: від авторизації до оплати. Є реєстрація й вхід через NextAuth (GitHub, Google або звичайний email/пароль), каталог з фільтрами за тістом, розміром, ціною та складниками, кошик і оформлення замовлення з онлайн-оплатою. Верстка на Tailwind CSS плюс компоненти ShadCN.

## Що є в проєкті

- Реєстрація та вхід через NextAuth.js (GitHub, Google, email/пароль)
- Каталог (піца, сніданки, закуски, коктейлі, напої) з фільтрами за тістом, розміром, ціною й інгредієнтами
- Кошик з динамічним перерахунком суми
- Оформлення замовлення з онлайн-оплатою
- Email-листи через Resend: підтвердження реєстрації, посилання на оплату, підтвердження оплаченого замовлення (детальніше нижче, там є нюанс)
- Валідація форм на React Hook Form + Zod
- Тост-повідомлення через react-hot-toast
- Стан застосунку на zustand

## Стек

Next.js, React, TypeScript, Prisma, NextAuth.js, Tailwind CSS, ShadCN, React Hook Form, Zod, React Hot Toast, Resend, Lucide React, Zustand

## Встановлення та запуск

1. Клонувати репозиторій:

   ```bash
   git clone https://github.com/RudenkoOleksandr02/pizzahub.git
   cd pizzahub
   ```
2. Встановити залежності:

   ```bash
   npm install
   ```
3. Створити файл `.env` у корені проекту та вказати необхідні змінні середовища:

   ```bash
   DATABASE_URL=

   NEXT_PUBLIC_API_URL=
   NEXT_PUBLIC_DOMAIN=

   RESEND_API_KEY=
   RESEND_FROM_EMAIL=

   LIQPAY_PUBLIC_KEY=
   LIQPAY_PRIVATE_KEY=
   LIQPAY_RESULT_URL=

   GITHUB_ID=
   GITHUB_SECRET=

   NEXTAUTH_SECRET=
   NEXTAUTH_URL=

   GOOGLE_CLIENT_ID=
   GOOGLE_CLIENT_SECRET=
   ```
4. Запустити сервер розробки:

   ```bash
   npm run dev
   ```
5. Відкрити [http://localhost:3000](http://localhost:3000) у браузері.

## Про листи на email (важливий нюанс)

Листи через Resend надсилаються у трьох місцях: коли реєструється новий користувач (код підтвердження), коли оформлюється замовлення (посилання на оплату) і коли оплата пройшла успішно (підтвердження замовлення). Все це йде через одну функцію `sendEmail` (`lib/send-email.ts`), а адреса відправника береться зі змінної `RESEND_FROM_EMAIL`.

Тепер сам нюанс. Це пет-проєкт для портфоліо, тож я не став купувати й верифікувати домен для Resend. Сенсу платити за домен, яким ніхто реально не користуватиметься, не бачу. Зараз листи йдуть з тестової адреси `onboarding@resend.dev`, а в Resend є обмеження: з цієї адреси лист долетить тільки на email, який прив'язаний до мого акаунта. На будь-яку іншу адресу Resend просто відмовить (403).

Уся логіка при цьому працює нормально: і генерація коду, і створення замовлення, і обробка колбеку від LiqPay. Просто сам лист не долетить, якщо тестувати не з моєї пошти. Хочете перевірити наживо - напишіть мені, додам ваш email до акаунта Resend.

Якщо колись знадобиться, щоб працювало для всіх - рішення просте: верифікувати домен на [resend.com/domains](https://resend.com/domains) і поміняти значення `RESEND_FROM_EMAIL`. Коду це не торкнеться.
